docker概念 #

  • 使用容器化部署技术，给应用程序封装独立的运行环境。运行环境就是一个容器，运行容器的计算机被称为宿主机器。
  • 容器和虚拟机最大的区别是：docker容器之间共用一个系统内核，而虚拟机则需要一个完整的操作系统内核。docker容器比虚拟机更轻量级，启动速度更快，资源占用更少。
  • docker镜像与容器：docker镜像是docker容器的模板。 可以类比为软件安装包，而容器是安装出来的软件。也可以类比为现实世界的糕点模具，我们可以使用一个模具做出很多个糕点。
  • docker镜像仓库：是用来存放分享镜像的地方。
    docker官方镜像仓库

docker pull #

用来从仓库下载镜像，例如下载nginx镜像：docker pull docker.io/library/nginx:latest
docker.io: 这部分是docker仓库的注册表地址。docker.io是docker hub官方的仓库。官方仓库可以省略地址。
library: 这部分是命名空间（镜像作者的名字）。library是官方的命名空间。官方的命名空间可以省略。
:latest: 镜像的版本号。latest是最新版本，可以忽略。
简化后的吗，命令为：docker pull nginx，表示从官方下载最新的nginx镜像。

官方镜像地址：https://hub.docker.com/
国内镜像地址：https://docker.fxxk.dedyn.io

docker pull 选项 #

  • --platform=XXX ：拉取特定CPU架构的镜像。例如：docker pull --platform=linux/arm64/v8 nginx。默认情况下，Docker会自动选择最合适的镜像。

docker images #

列出所有下载到本地的镜像

docker rmi id/name #

删除镜像 rmi: 表示移除镜像 id/name: 镜像的id或者名称

docker run name #

使用镜像创建并运行一个容器
name: 镜像名称

  • -d: 表示detached mode，后台运行容器，不会阻塞当前的窗口。例如：docker run -d nginx

  • -p: 映射端口，格式为：-p host_port:container_port
    每个容器都运行在一个独立的虚拟环境里面。容器的网络与宿主机是隔离的，默认情况下必能从宿主机直接访问到docker的内部网络。
    例如：docker run -d -p 80:80 nginx。冒号前面是宿主机的端口，冒号后面是容器的端口。

  • -v: 挂载卷（volume），格式为：-v host_path:container_path
    挂载卷，将宿主机的目录与容器内目录进行绑定。容器内的文件修改会影响到宿主机的文件夹。在宿主机上对文件进行修改，也会影响到容器内文件。
    作用：数据持久化，删除容器后数据不会丢失。 注意：在使用-v时，宿主机的目录会覆盖容器内的目录，所以需先创建好宿主机目录。

  • -e: 设置环境变量
    例如给mongo镜像设置环境变量MONGO_INITDB_ROOT_USERNAME(账号)和MONGO_INITDB_ROOT_PASSWORD(密码)

    docker run -d \ 
-p 27017:27017 \
-v mongodb_data:/data/db \
-e MONGO_INITDB_ROOT_USERNAME=admin \
-e MONGO_INITDB_ROOT_PASSWORD=password \
mongo

  • --name：容器名称 容器名称在宿主机中必须是唯一的，不能重复。

  • -it: 交互式运行，进入命令行。

  • --rm: 运行结束后删除容器。

-it 与 --rm 一般同时使用，用于调试一个容器。

  • --restart：容器退出后的重启策略
    • always：总是重启，包含容器内部错误崩溃，或者宿主机断电场景。
    • unless-stopped：除非被手动停止，否则一直重启。手动停止的容器就不会重启。

docker volume create volume_name #

创建一个名为 volume_name 的卷。 在创建容器时可以用-v参数来使用这个卷。例如：docker run -d -p 80:80 -v volume_name:/var/www/html nginx

docker volume inspect volume_name #

显示卷的详细信息，可以查看挂载卷的位置等信息。

docker volume list #

列出所有命名卷。

docker volume rm volume_name #

删除一个命名卷。

docker volume prune -a #

删除所有未使用的卷。

  • -a: 列出所有容器，包括停止的容器

  • -f: 强制删除

docker inspect container_id/name #

查看容器的日志

  • -f: 滚动查看日志

在容器中执行命令 command: 容器中要执行的linux命令，例如查看进程：docker exec nginx ps -ef

  • -it: 启动一个交互式shell， 例如：docker exec -it nginx /bin/sh

DockerFile #

DockerFile 是一个文件，它详细描述一个镜像是如何制作的，可以类比为一个糕点模具的图纸。

bash
# Dockerfile 

# FROM 表示基于哪个镜像构建镜像
FROM python:3.13-slim  

# WORKDIR 切换到镜像内的一个目录，作为工作目录
WORKDIR /app  

# 下面的命令都是在上面的 WORKDIR 目录下执行  

# copy 拷贝文件 第一个点表示宿主机的当前目录，第二个点表示镜像内的当前工作目录，也就是 /app 目录
COPY . .  

# 安装依赖  
# RUN 表示在镜像内执行命令
RUN pip install -r requirements.txt  

# EXPOSE 暴露端口，这个只是一个提示，告诉 Docker 容器，这个容器对外 exposes 端口 8000  
# 真正的端口号是 -p 设置的端口
EXPOSE 8000  

# CMD 启动命令，每当容器启动的时候都会执行这个命令  
CMD ["python3", "manage.py"]  

# entrypoint与CMD一样，但是优先级更高，不容易被覆盖
# ENTRYPOINT [ "python3", "manage.py" ]

Docker 网络 #

bridge 模式 #

docker 的网络默认是 bridge（桥接）模式，所有的容器都在一个网段内。每个容器都分配了一个内部IP地址，一般是172.17 开头，在这个内部网络中，容器之间可以通过 IP 地址进行相互访问。
容器的网络和宿主机的网络是隔离的，可以用 docker network create 创建子网，默认情况下，创建出来的子网也是桥接模式的一种，可以指定容器加入不同的子网，同一个子网的容器可以互相通信，跨子网的容器不可以通信。
创建子网的好处是：统一个子网的容器可以用 容器的名字互相访问，不必使用内部的IP地址

  • 创建子网络

    shell

    host 模式 #

    host 模式是指容器直接使用宿主机的网络，容器和宿主机共享同一个IP地址，无需用-p进行端口映射。
    容器内的服务直接运行在宿主机的端口上，通过宿主机的IP和端口，就能访问到容器。

docker compose #

有时候一个完整的应用是有很多个部分组成的，比如一个web应用可能需要前端、后端、数据库等多个部分。 docker compose 就是可以把这些部分组合在一起，形成一个完整的应用。
docker compose 是一个容器编排技术。 docker compose 使用 yaml 文件管理多个容器，里面描述容器是如何创建、如何协同工作的。

docker compose 文件格式 #

yaml

services:
  my_mongo:
    image: mongo
    environment:
      MONGO_INITDB_ROOT_USERNAME: admin
      MONGO_INITDB_ROOT_PASSWORD: password
    volumes:
      - mongodb_data:/data/db

  my_mongo_express:
    image: mongo-express
    ports:
      - "8081:8081"
    environment:
      ME_CONFIG_MONGODB_SERVER: my_mongo
      ME_CONFIG_MONGODB_ADMINUSERNAME: admin
      ME_CONFIG_MONGODB_ADMINPASSWORD: password

    depends_on:
      - my_mongo

docker compose 不需要创建子网，同一个docker compose中的容器会被放入到同一个子网 可以自定义容器的启动顺序

docker compose 命令 #

  • docker compose up
    启动所有的服务，创建容器并运行。
    -d: 后台运行容器，例如：docker compose up -d -f: 指定docker compose文件，例如：docker compose -f docker-compose.yml up -d

  • docker compose down
    停止所有的服务，删除容器。
    -v: 删除卷，例如：docker compose down -v

  • docker compose stop
    停止所有的服务，但不删除容器。

  • docker compose start 启动停止的服务。
